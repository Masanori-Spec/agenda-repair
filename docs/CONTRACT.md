# Input and module contract
ES modules, no runtime deps/build step. Static index.html + src/*.js/css. Node >=22.

Problem schema exact keys only:
{version:1,title:string,day:{start:int,end:int,step:int},rooms:[{id,label}],resources:[{id,label}],sessions:[{id,title,duration,start,roomId,earliestStart,latestStart,eligibleRoomIds:[id],resourceIds:[id],pinned:boolean}],blackouts:[{id,type:'room'|'resource',targetId,start,end}]}
Minutes 0..1440, day start<end, step1..60; start/earliest/latest on grid relative day.start. Duration integer>=1; not necessarily multiple step. Session baseline must fit day; repair eligibility/window may exclude original placement. Window must fit day when combined duration. IDs regex /^[A-Za-z0-9][A-Za-z0-9_-]{0,39}$/ and unique within each collection. Max title/label120 chars. No control characters. Up to20 sessions,8 unpinned,6 rooms,8 resources,24 blackouts. Every unpinned session nominal domain=(1+(latest-earliest)/step)*eligibleRoomIds.length <=120. Blackouts half-open intervals in day (not grid-restricted). Resource IDs opaque equipment only; do not upload personal data. Inputs max100KB, strict schema rejects unknown fields.

src/model.js exports LIMITS, validateProblem(input) => {ok:true,value:normalized-clone} OR {ok:false,errors:[string]}, parseProblem(text) same; minuteLabel(n); baselineAssignments(problem); summarizeChanges(problem, assignments).
src/verify.js exports verifyAssignments(problem,assignments)=>{ok,errors:[string]}; independent verifier (no solver helpers), checks completeness, duration/grid/windows/eligible/pins/blackouts/room and resource overlap.
src/solver.js exports async solve(problem,{nodeBudget=200000,shouldCancel=()=>false,onProgress=()=>{},yieldEvery=512}={}) => {status:'optimal'|'feasible'|'infeasible'|'unknown',reason:'complete'|'budget'|'cancelled',assignments:[{id,start,roomId}]|null,objective:{changedSessions,totalShiftMinutes,roomChanges,tieBreak:[number]}|null,nodes:number,diagnostics:[string]}. objective tieBreak iterates session IDs ASCII order; each pair is start then rank of room ID ASCII order. All other comparisons numeric lexicographic. Optimal/infeasible only on complete search; budget/cancel => feasible with incumbent or unknown without. Solver should validate throw on invalid problem. onProgress gets {nodes,objective}. No elapsed timing affects search.
src/worker.js protocol request {type:'solve',requestId,problem,nodeBudget} and {type:'cancel',requestId}; responses {type:'progress'|'result'|'error',requestId,...} with progress or result payload. Each solve starts fresh worker instance in UI, terminate previous; request IDs reject stale results; cancel message graceful.
src/demos.js exports DEMOS=[{id,label,description,problem}] (3 synthetic realistic demos).
Interface files: src/app.js, src/style.css and index.html. No innerHTML using user values. Worker loads ./worker.js via import.meta.url. Baseline retained; explicit proposed download includes {version:1,problem,proposal:{assignments,objective,status,reason}} (export is auditable proposal, import only original problem schema; separate baseline JSON download). Import errors leave old state unchanged. The blackout form and pin toggles edit constraints; any change invalidates proposal. No localStorage or outbound network requests.
